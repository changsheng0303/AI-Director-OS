# 多视角会诊（Multi-Perspective Consultation）

> 来源：剧本医生·圆桌会诊方法论增量提取（2026-08 融合）
> 用途：红果审剧本的**问题暴露层**——在红果做出平台裁决前，先用多立场视角把问题照出来
> 定位：**只暴露，不裁决**。最终评级/改稿优先级仍由红果（内容负责人方法论）判定
> 触发：用户说"会诊/多视角看看/几个角度审一下"，或红果审稿前希望先照全貌

## 与红果主流程的关系

```
多视角会诊（问题暴露层：3-5 立场轮替）→ 红果审剧本（裁决层：评级+生死线+P1/P2/P3）→ 改稿
```

**裁决权唯一**：会诊产出问题清单与分歧度，红果依据 38 条铁律做最终判定。会诊意见与铁律冲突时，铁律优先。

## 一、防"和稀泥"硬规则（会诊质量底线）

1. **立场宣言绑定**：每个立场开场必须声明身份（商业制片/核心受众/平台采购…），陈述全程援引立场——"作为商业制片，我看到的是这戏能不能让资方掏钱"，禁止无立场空谈。
2. **禁止和稀泥词**：发言中禁用"还行""差不多""可能""或许""我觉得也许""也不能说不好""我同意XX的看法"（除非紧接反驳）。
3. **必须有具体证据**：每条意见必须引用至少 1 段剧本原文（标场号/集号）。❌"节奏太慢" ✅"第 3 场用 500 字写做早餐但无冲突信息——按短剧节奏浪费 30 秒留人时间"。
4. **必须有立场冲突**：若所有立场看法一致，需追加一段自我警觉——"会诊一致度过高，可能召集偏差：①剧本真没大问题（罕见）②立场过于接近"。建议加一个反对立场再试。
5. **禁止立场 OOC**：商业制片不会突然关心主题深度；审查官不会突然夸角色弧光。该立场盲区内的意见交给对口立场说。
6. **禁止虚构履历**：可说"作为类型片编剧，我经手过几个悬疑短剧"，禁止"我当年写《狂飙》时……"。

## 二、三立场模式（默认，轻量）

红果审稿时默认用三个立场，避免全量评委拖慢流程：

```markdown
【平台负责人立场】（承接红果市场方法论）
- 看到什么（引用原文）：____
- 判断：____（必须援引平台/市场逻辑）
- 核心质疑：____

【目标观众立场】（按题材选：如女频仙侠→女主控观众；男频都市→爽感观众）
- 看到什么（引用原文）：____
- 判断：____（必须援引观看体验逻辑）
- 核心质疑：____

【编剧立场】（按红果铁律审视执行质量）
- 看到什么（引用原文）：____
- 判断：____（必须援引剧作逻辑，如冲突/人设执行/爽感兑现）
- 核心质疑：____
```

**立场可换**：`会诊 立场=[商业制片, 审查官, 影评人]` 自定义。单点问题时按问题类型选对口立场（见第四节）。

## 三、分级归纳（主治医生输出）

三立场陈述后，按共识度分级输出：

```markdown
🔴 必改（≥2 立场独立提到，强烈共识）
  问题：____ ｜ 出处：第__场/第__集 ｜ 立场来源：A+B ｜ 分歧度：低

🟡 建议（仅 1 立场提到，但有真知灼见）
  问题：____ ｜ 立场来源：A ｜ 分歧度：高 ｜ 备注：参考但不必照办

🟢 别动（≥2 立场一致认可的优点）
  优点：____

🚨 红果待裁决项（交回红果层）
  一句话：会诊暴露的核心矛盾，交由红果依据铁律定论
```

**裁决交接**：归纳末尾必须明确"哪些交回红果裁决"，不得自己下结论。

## 四、单点会诊（按问题选立场）

| 单点问题 | 自动召集立场 |
|---|---|
| logline 抓不抓人 | 平台负责人 + 目标观众 + 商业制片 |
| 主角讨不讨喜 | 核心受众 + 演员经纪 + 责任编辑 |
| 第三幕收得住吗 | 编剧 + 责任编辑 + 二刷观众 |
| 过审风险 | 审查官 + 法律/备案 + 商业制片 |
| 爽感够不够重 | 目标观众 + 商业制片 + 平台负责人 |

## 五、与现有 skill 的边界

| 相关 skill | 边界 |
|---|---|
| 红果审剧本主流程 | 本文件是红果的**问题暴露层**；评级/生死线/改稿优先级仍走红果主流程 |
| `微短剧创作/references/四视角顾问审稿.md` | 四视角=大纲定稿前用（编剧/制片/观众/平台，偏选题）；本文件=剧本审稿时用（偏执行质量+市场验证）。两者按阶段分工，不重复调用 |
| `drama-script-iteration/references/台词七维诊断.md` | 台词七维=逐句诊断台词；本文件=整本/单集/单点的多立场会诊。台词专项问题时优先台词七维 |
