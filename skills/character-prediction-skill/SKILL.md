# 人物行为预测与一致性控制

## 定位

这是 IP、剧本、分镜和视频提示词可共用的轻量子模块，不是总控，也不重写主流程的成品。只根据已确认的人设，判断角色的态度、情绪、动作、台词倾向和行动决策。

## 输入

```text
角色核心：稳定人格、关键矛盾、欲望/恐惧、表达原则、OOC边界
当前状态：可选；目标、情绪、压力、关系、已知信息、身心状态
当前关系：对象和关系级别
场景：事件、公开/私下、严重程度、剧情阶段、边界/危险
模式：FAST / STANDARD / STRICT
```

## 规则

1. 当前人格和当前状态优先；历史背景默认不加载。
2. 先判断事件对人物的意义，再判断情绪与外部表现。
3. 每次只取本场相关的 2–4 项特征；内部情绪须经过人物表达方式过滤。
4. 行为须能回溯到人物设定；弱推断、单次表现和低置信度结果不得写回永久人设。
5. 关系变化体现为原有规则的阈值变化，不能以突然人格反转替代。
6. MBTI、星座、固定萌点或固定动作只能弱辅助，不能决定行为。

## 模式

- **FAST（默认）**：主 Skill 内部完成轻量判断；不单独调用预测或审核。
- **STANDARD**：仅用于高光、情绪、关系推进或冲突戏；输出最小人物反应。
- **STRICT**：仅用于重大转折、首次立人设、明显 OOC 风险或用户要求审核；末尾追加极简 Reviewer。

## 输出

```text
态度：
情绪：
动作：
台词：
行动：
```

单角色单场景通常控制在 50–120 中文字。只有用户要求解释、存在多种合理预测、可能 OOC、信息不足或需要写回时，才追加：`依据`、`置信度`、`review_required`。

## 审核与写回

当行为冲突于 Core、需要突破 OOC、关键剧情存在多种同等合理反应、关系变化过大、需要新增永久特征或信息不足时，设置 `review_required: true`。Reviewer 仅输出 `PASS` 或包含问题、依据和建议的最小 `WARNING`。

场景预测默认是临时状态。只有经用户确认、稳定重复、成为标志性行为、持续影响后续剧情或明确属于人物成长时，才形成候选写回；写回前进行一致性检查。

## Token 控制

核心人物 Core 建议 250–450 中文字、次要人物 120–250 字；普通场景使用 FAST；历史默认 0 token；不重复传递整份人物解释；多个场景集中审核。
