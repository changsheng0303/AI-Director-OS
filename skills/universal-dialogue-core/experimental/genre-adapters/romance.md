# Romance Dialogue Adapter v1.0

## Mission

用**关系距离变化**制造浪漫，而不是靠持续直白表达、甜言蜜语或强行暧昧。

## Preferred Tactics

- test_closeness：用小问题确认自己在对方心中的位置；
- indirect_care：用事实、命令、提醒代替直接关心；
- selective_disclosure：只透露一部分真实感受；
- retreat_after_exposure：表达过多后立刻撤回；
- boundary_negotiation：靠称呼、距离、私密信息改变关系边界；
- jealousy_displacement：把嫉妒包装成别的问题；
- shared_memory：用只有两人理解的回调建立亲密；
- missed_timing：两人的真实意图短暂错开。

## Beat Bias

暧昧：

`Proximity → Test → Near Exposure → Retreat → Residue`

关系推进：

`Distance → Vulnerability → Response → Boundary Shift`

告白 / 确认关系：

`Pressure → Failed Avoidance → Choice → Clear Commitment → Aftershock`

## Rhythm Rules

- 越接近真实感情，越允许句子变短；
- 高情绪处允许停顿和未完成句；
- 不要双方同时拥有完美表达能力；
- 关键回应前留出反应空间；
- 称呼变化可作为关系变化，但不能滥用。

## Subtext Rules

优先表达：

`我想靠近你，但我承担不起被拒绝的风险。`

潜台词可以来自：

- 试探；
- 嘴硬；
- 错开视线；
- 过度普通的关心；
- 记住小事；
- 故意改变话题；
- 只对某人使用的语言模式。

## Anti-Patterns

- 每句话都像情书；
- 用占有、控制或越界行为替代亲密；
- 没有铺垫就突然深情告白；
- 角色不断自我分析感情；
- 所有暧昧都靠脸红、结巴和“笨蛋”；
- 只提高甜度，不改变关系状态。

## Payoff Rule

场景结束至少改变一项：

- intimacy；
- trust；
- vulnerability；
- relationship boundary；
- mutual knowledge；
- unresolved romantic tension。

## Extra Checks

- 两人是否真的比开场更近或更远？
- 台词是否保留角色边界与自主性？
- 是否存在“只换称呼就当作关系推进”的假变化？
- 关键情绪是否由动作/停顿承担一部分？
