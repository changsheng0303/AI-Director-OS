# Codex 原生图像资产流程

## 1. 先查复用

对每个角色变体、场景变体和道具变体按以下顺序查找：

1. 同一剧集、同一套装的已锁定资产；
2. 同一剧的其他套装，确认年龄、造型、时间和状态兼容；
3. 兼容跨剧资产，只允许通用场景或无身份道具，人物默认不可跨剧复用；
4. 无可用资产才进入生成缺口。

`04-资产索引.md`至少包含：

| 槽位 | 类型 | 资产ID/变体 | 来源 | 状态 | 文件路径 | 用途 | 不可漂移项 |
| --- | --- | --- | --- | --- | --- | --- | --- |

状态只使用 `reused`、`candidate`、`locked`、`rejected`、`missing`。只有 `locked` 可进入正式视频槽位。

## 2. 固定图像执行端

- 所有新角色、场景和道具图片使用当前 Codex 会话提供的原生 `image_gen` / 图像生成能力。
- 不调用 Midjourney、Alibaba MJ、Dreamina 图片命令或其他图片 API。
- 场景提示词使用自然语言和明确空间关系，不附加 `--ar`、`--s`、`--q` 等 MJ 参数。
- 如果要编辑已有图片，先查看目标图片，再把所有目标图作为明确参考传给原生图像编辑能力。

## 3. 请求预览与付费门

将待生成批次写成 JSON 计划，示例结构：

```json
{
  "schemaVersion": 1,
  "kind": "image",
  "project": "项目名",
  "requests": [
    {
      "id": "CHAR-001-base",
      "backend": "codex-image",
      "model": "native",
      "prompt": "完整自包含提示词",
      "ratio": "9:16",
      "references": ["绝对或相对文件路径"],
      "output": "09-资产/characters/CHAR-001_base.png"
    }
  ]
}
```

运行：

```bash
/usr/bin/python3 scripts/request_fingerprint.py /absolute/path/to/image-plan.json
```

向用户展示任务数量、逐项 ID、模型/后端、画幅、参考文件、提示词或提示词文件、输出路径、逐项指纹和总指纹。只有用户对该批次明确回复“提交资产”“提交图片”或等价授权后才调用图像生成。

## 4. 小批执行与验收

- 先生成一个代表性角色、一个场景或一个道具样例；用户明确要求整批时才按已批准数量执行整批。
- 生成结果保存到项目资产目录，不把预览、调试图或已拒绝候选标成 `locked`。
- 打开查看每个候选，检查文件可读、画幅、主体数量、身份/结构、服装/材料、道具数量、背景和明显生成残渣。
- 角色四格重点检查四格边界、同一身份、无重复头部/肢体、正侧背视图和装备一致性。
- 场景重点检查空间拓扑、入口/出口、固定地标、光源方向和无意外人物。
- 道具重点检查尺度、结构、可动部件、持握关系和无额外部件。
- 只有人工选择或明确规则接受的最终文件进入 `04-资产索引.md`，并记录文件大小、尺寸和 SHA-256。

提示词或参考图发生变化后，原请求指纹失效；重新生成预览并重新确认，禁止借旧授权扩量。
